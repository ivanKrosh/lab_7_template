# Лабораторна робота №7 — шаблон рішення

Заготовка до лабораторної роботи №7 «Робота з файлами» курсу «Системне програмування»
(ВСП «Фаховий коледж інформаційних систем і технологій КНЕУ ім. Вадима Гетьмана»).

Усі проєкти вже налаштовано так, як вимагає методичка. **Не змінюйте налаштувань**, крім *Working Directory* проєкту `Step1_where` — це частина кроку 1.

## Склад рішення

| Проєкт | Файл | Крок | Що в ньому |
|---|---|---|---|
| `Step1_where` | `where.c` | 1 | поточний каталог, повний шлях файлу, читання в режимах `"r"` і `"rb"`, створення `where_out.txt` |
| `Step2_modes` | `modes.c` | 2 | таблиця режимів відкриття (`table`), номери дескрипторів (`three`), один файл (`open <файл> <режим>`) |
| `Step3_io` | `io.c` | 3 | три функції читання й запису, які треба написати, і готові перевірки до них |
| `Step4_bugs` | `bugs.c` | 4 | три функції з помилками в роботі з файлами — їх треба знайти й виправити; номер функції — аргумент `1`…`3` |
| `Step5_variant` | `variant.c` | 5 | заготовка програми за вашим варіантом |
| тека `data` | `marks.txt` | 1–4 | оцінки групи: вісім рядків «прізвище оцінка» |

## Як працювати

1. Відкрити `Lab7.slnx` у Visual Studio 2026 (*File → Open → Project/Solution*).
2. На панелі зверху вибрати **Debug** і **x64**.
3. Правою кнопкою на проєкті потрібного кроку → **Set as Startup Project**.
4. `F5` — запуск під налагоджувачем, `Ctrl+F5` — без нього.

**Аргументи командного рядка** змінюються в *Properties проєкту → Configuration Properties → Debugging → Command Arguments*.

**Запуск з терміналу** (*View → Terminal*, відкривається в теці рішення):

```
cd data
..\x64\Debug\Step2_modes.exe three
$LASTEXITCODE
```

## Що вже налаштовано

| Параметр | Значення | Навіщо |
|---|---|---|
| *C/C++ → General → Warning Level* | `/W4` | попередження рівня 4; помилки кроку 4 компілюються **без** попереджень — це частина роботи |
| *C/C++ → General → SDL checks* | Yes (`/sdl`) | частина попереджень стає помилками |
| *C/C++ → General → Support Just My Code Debugging* | No (Debug) | без зайвого виклику на початку кожної функції |
| *C/C++ → Code Generation → Basic Runtime Checks* | Both (`/RTC1`, Debug) | перевірка запису за межу локального масиву; потрібна в кроках 3–5 |
| *C/C++ → Command Line → Additional Options* | `/utf-8` | вихідні файли збережено в UTF-8 |
| *Debugging → Working Directory* | `$(SolutionDir)data\` у кроках 2–4; типове `$(ProjectDir)` у кроках 1 і 5 | кроки 2–4 знаходять `marks.txt` і пишуть свої файли в `data`; у кроці 1 типове значення — частина експерименту |
| *Debugging → Command Arguments* | `table` у кроці 2, `1` у кроці 4 | щоб `F5` одразу запускав потрібний режим |

У кожному файлі перший рядок — `#define _CRT_SECURE_NO_WARNINGS`: без нього MSVC вимагає замість `fopen` і `fscanf` нестандартні `fopen_s` і `fscanf_s` (попередження C4996, з `/sdl` — помилка).

## Відомі граблі

**Крок 1 під `F5` друкує `marks.txt: No such file or directory`.** Так і має бути до зміни *Working Directory*: поточний каталог — тека проєкту.

**`Step3_io` повертає ненульовий код і друкує `FAIL`.** Так і має бути, поки функції не написано: перевірки показують, які випадки ще не працюють.

**`Step4_bugs 2` у Debug зупиняється з повідомленням *Run-Time Check Failure #2*.** Так і має бути до виправлення.

**`Step4_bugs 3` не завершується.** Так і має бути до виправлення. *Debug → Break All* — подивитися, де стоїть програма; `Shift+F5` — зупинити.

**У теці `data` з'являються нові файли й теки.** Їх створюють програми кроків 1–4. Git їх ігнорує, їх можна вільно видаляти. Якщо не видаляється `data\modes_test`, зніміть атрибут: `attrib -r data\modes_test\readonly.txt`.

**Кирилиця в аргументах командного рядка перетворюється на `?`.** Імена файлів і тек в аргументах — латиницею.

**Рішення не відкривається.** Файл збережено в новому форматі `.slnx`. Оновіть Visual Studio або відкрийте потрібний `.vcxproj` напряму.
